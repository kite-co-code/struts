# Naming

Two layers of custom properties, and class names that follow from them. If you're adding something and unsure which layer it belongs to, ask: **is this owned by one pattern, or read by several?**

## Custom properties

### Global layer: single dashes, Tailwind's shape

Tokens and knobs that several patterns read. Use Tailwind's namespace wherever one exists, so the token also becomes a utility.

| Kind | Names | Where |
| --- | --- | --- |
| Theme tokens | `--color-*`, `--text-*`, `--font-*`, `--radius-*`, `--ease-*`, `--container-*`, `--breakpoint-*`, `--animate-*`, `--spacing`, `--default-transition-*` | `css/tokens/theme.css` (colours generated from `colors.config.json`) |
| Shared knobs | `--gutter`, `--space-base`, `--space-layout`, `--gap`, `--col-gap`, `--row-gap`, `--cols`, `--flow-space`, `--focus-color`, `--focus-width`, `--focus-offset`, `--rule-color`, `--rule-width` | `css/tokens/globals.css` |

Colour tokens come in pairs: `--color-{name}` and `--color-{name}-foreground`. Roles (`background`, `foreground`, `accent`, `secondary`, `error`) are aliases of palette colours, and they are what surfaces change.

### Scoped layer: BEM

A variable owned by one pattern is named after it:

```
--{block}[__{element}]--{property}[--{state}]
```

| Part | Rule | Examples |
| --- | --- | --- |
| block | The pattern's class | `--btn--…`, `--input--…`, `--layout--…` |
| element | BEM element, if the variable belongs to one | `--btn__icon--…`, `--list-styled__marker--color` |
| property | The CSS property it feeds, logical where there's a choice | `--btn--background-color`, `--prose--max-inline-size` |
| state | Last, named after the pseudo-class | `--btn--background-color--hover`, `--checkbox--background-color--checked` |

States: `--hover`, `--focus`, `--active`, `--checked`, `--disabled`, `--expanded`.

**Short forms**, for when CSS has no single property:

| Short form | Means |
| --- | --- |
| `padding-x` | `padding-inline` (both sides) |
| `padding-y` | `padding-block` (both sides) |
| `gap` | space between children, whether `gap`, margins or something else |
| `size` | inline and block size together |
| `icon-size` | the size of an icon inside the block |

**Internal values** a block computes for itself (not knobs, never set from outside) start with an underscore: `--_content`, `--_wide` in `layout-grid`.

### Rules

- **Modifiers never own variables.** `btn--secondary` sets `--btn--…` variables; it never declares `--btn--secondary--…`. Modifiers set only the block's variables, so Tailwind sorts them after the block and they win.
- **One owner → scoped. Several readers → global.** If a second pattern starts reading a scoped variable, promote it to the global layer.
- **Where a variable is declared decides what can override it.** See [decision 003](decisions/003-custom-property-api.md):
  - Knobs only variants set are declared on the block itself (`.btn { --btn--padding-x: 1em }`), never on `:root`, so `var()` resolves at the element and follows its context.
  - Knobs a context may set are never declared. They're read with a fallback: `var(--link--color, var(--color-accent))`.
  - Hover and other states derive from the base value with `color-mix()`, so they follow too.

## Classes

| Kind | Shape | Examples |
| --- | --- | --- |
| Utilities | Tailwind's: `name` or `name-{value}` | `cols-3`, `stack-16`, `layout-wide`, `layout-width-sm`, `scroll-lock` |
| Patterns | BEM, written as `@utility` so variants work | `btn`, `btn--secondary`, `btn__icon`, `md:btn--small` |
| Colour contexts | `surface-{colour}`, `on-{colour}` | `surface-blue`, `on-neutral` |
| Type | `type-{style}` composes family, weight, leading and size; `text-{size}` is size only | `type-h2`, `text-h2` |

Patterns are `@utility` rather than plain classes so they can be `@apply`'d and take variants (`md:cols-4`, `hover:…`, `dark:…`).

## JS hooks

Behaviour hangs off `data-*` attributes, never classes. Classes are for styling and can change freely.

| Hook | Script |
| --- | --- |
| `data-disclosure` (on the target) | `js/disclosure.ts` |
| `data-dialog` (on the `<dialog>`), `data-dialog-open`, `data-dialog-close`, `data-dialog-template`, `data-dialog-slot` | `js/dialog.ts` |
| `data-animate`, `data-animate-stagger`, `data-playing` (set by script) | `js/animate.ts` |
| `data-show-expanded`, `data-hide-expanded`, `data-show-collapsed`, `data-hide-collapsed` | CSS only, `css/utilities/aria-expanded.css` |
| `data-scheme="light"`, `data-scheme="dark"` | CSS only, generated by `postcss/color-system.js` |

Options read from data attributes are prefixed with the hook's name (`data-disclosure-animate`, `data-dialog-modal`).
